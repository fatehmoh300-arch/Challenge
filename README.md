# تحدّي | CHALLENGE

منصة عربية RTL لإنشاء تحديات شخصية وجماعية، وإدارة الأهداف والإنجازات والمنافسة بين المشاركين. مبنية على Next.js 16 وTypeScript وTailwind CSS 4 وSupabase وRecharts.

## المبدأ

لا يوجد تحدٍّ ثابت أو تقويم مفروض. ينشئ كل منظّم تحدّيه، ويحدد عنوانه ووصفه ومدته وخصوصيته وأهدافه ونقاطه وقواعده وعدد المشاركين. يستطيع الحساب الواحد الانضمام إلى عدة تحديات والتبديل بينها من لوحة التحكم.

## إعداد قاعدة البيانات

شغّل ملفات `supabase/migrations` بالترتيب التصاعدي:

1. `20261127034306_challenge_schema.sql`
2. `20261127034323_hardening_and_scoring.sql`
3. `20261127034417_advisor_hardening.sql`
4. `20261127051952_public_challenge_catalog.sql`
5. `20261127052044_public_challenge_policy_tuning.sql`
6. `20261127052243_challenge_creation_and_open_join.sql`
7. `20261127105043_flexible_challenges_progression.sql`
8. `20261127105319_fix_progress_rpc_output_ambiguity.sql`
9. `20261127105346_advisor_indexes_and_policy_cleanup.sql`
10. `20261127142000_p0_security_scoring_integrity.sql`

أُعيدت تسمية ملفات الترحيلات المحلية لتطابق أرقام الإصدارات المسجلة فعلياً في Supabase؛ لم يُعَد تنفيذ أي ترحيل قديم. على قاعدة الإنتاج الحالية، يجب أن يكون سجلّ الإصدارات 001–009 موجوداً مسبقاً. نفّذ فقط الترحيل 010 بعد مراجعة تغييره ونتائج CI، ولا تعِد تطبيق أي ترحيل سابق.

في Supabase Authentication → URL Configuration، اضبط Site URL وأضف عنوان الموقع المحلي وعنوان Vercel إلى Redirect URLs مع المسار `/auth/callback`.

## تشغيل التطبيق

1. انسخ `.env.example` إلى `.env.local`.
2. أضف `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` من إعدادات مشروع Supabase.
3. نفّذ `npm install` ثم `npm run dev`.
4. أنشئ حساباً ثم أنشئ تحدياً من صفحة التهيئة. لا تُضاف أهداف افتراضية تلقائياً.
5. من «إدارة التحدّي» أضف الأهداف وحدد نقاطها، وما إذا كانت إلزامية أو اختيارية، ثم شارك الدعوة أو انشر التحدّي ضمن الاستكشاف العام.

لا تضع مفتاح Supabase السري أو Service Role Key في المتصفح أو في GitHub؛ التطبيق لا يحتاجه.

## الوظائف

- إنشاء عدة تحديات عامة أو خاصة، وتعديل بياناتها ومدتها وسعتها وحالتها.
- الانضمام بدعوة، أو انضمام عام مفتوح، أو طلب انضمام يحتاج موافقة.
- اختيار سعة من 2 إلى 500 عضو. هذا حد تطبيقي وقاعدة بيانات، وليس نتيجة اختبار ضغط لـ500 مستخدم.
- تعريف أهداف داخل كل تحدٍّ، مع نقاط من 1 إلى 100 لكل هدف، وإلزامية/اختيارية وفترة سريان.
- تجميد النقاط المكتسبة عند تسجيل الإنجاز حتى لا تغيّر تعديلات الأهداف نقاط الإنجازات السابقة.
- حساب نقاط المنافسة من سجلات الإنجاز، لا من قيمة يكتبها المستخدم.
- مستويات خبرة تراكمية: مبتدئ (0)، ملتزم (100)، منضبط (300)، متقدم (700)، محترف (1500)، أسطوري (3000).
- شارات تلقائية للخطوة الأولى، وسلاسل 7 و30 يوماً، ومئة إنجاز، ومئة صفحة قراءة، و500 نقطة خبرة.
- جوائز رقمية للمراكز الثلاثة الأولى عند إكمال المنظّم للتحدّي.
- أدوار المنظّم والمشرف والمساعد والمشارك، مع صلاحيات مفصلة على مستوى كل تحدٍّ.
- موجز منشورات وتعليقات خاص بأعضاء التحدّي.
- لوحة ترتيب تعرض إحصاءات مجمعة؛ لا تكشف سجلات العادات أو القراءة التفصيلية للمشاركين الآخرين.

## قواعد النقاط

- يحدد المنظّم نقاط كل هدف عند إنشائه.
- كل إنجاز يحفظ عدد النقاط المعتمد وقت التسجيل في `habit_completions.points_awarded`.
- الأهداف الإلزامية تحدد اكتمال اليوم وسلسلة الاستمرارية؛ الأهداف الاختيارية تضيف نقاطاً ولا تمنع اكتمال اليوم.
- لا يمكن تغيير نقاط هدف قائم أو إلزاميته بعد بدء تسجيل السجلات؛ يمكن إيقافه وإضافة هدف جديد حتى تبقى النتائج التاريخية عادلة.
- إذا أُكمل التحدّي، يتوقف تسجيل الإنجازات الجديدة وتُمنح جوائز المراكز الثلاثة الأولى للمشاركين الذين جمعوا نقاطاً.

## الصلاحيات والخصوصية

- RLS مفعّل على جداول بيانات المستخدمين والتحديات والمشاركات والجوائز.
- سجلات الإنجاز والقراءة اليومية خاصة بصاحبها.
- قائمة المشاركين متاحة عبر RPC محمية بعضوية التحدّي؛ لا يمكن للمستخدم قراءة معرفات العضويات الأخرى مباشرة.
- رموز الدعوة مخزنة بصيغة hash، ولا تعرض مباشرة من جدول الدعوات.
- إنشاء الأدوار والصلاحيات مقيد بمالك التحدّي. يمكن تفويض إدارة الأعضاء والقواعد وطلبات الانضمام والإشراف على المنشورات.
- وظائف `SECURITY DEFINER` تستخدم `search_path` ثابتاً وصلاحيات تنفيذ محدودة. جدول الدعوات لا يملك سياسات قراءة مباشرة عمداً؛ إصدار الرموز واستهلاكها يتمان عبر RPCs محمية.

## الاختبارات

- `npm run test:rules` لاختبارات النقاط والتقويم والإنجازات.
- `npm run typecheck` لفحص TypeScript.
- `npm run build` لبناء نسخة الإنتاج.

## حدود النسخة الحالية

- دعم PWA قابل للتثبيت؛ التخزين المؤقت الحالي محدود للأيقونات وملف manifest، ولا يعني وجود مزامنة كاملة دون اتصال.
- إشعارات المتصفح لا تعمل بعد إغلاق التطبيق. Push يحتاج إعداد VAPID وخدمة إرسال وخلفية خادمية.
- رفع الصور الشخصية غير مكتمل.
- موجز المجتمع حالياً نصي (منشورات وتعليقات)؛ لا يتضمن مرفقات أو تفاعلات أو نظام بلاغات.
- حُدّدت سعة التحدّي حتى 500 مشارك، لكن لم يُنفذ اختبار تحميل لهذا العدد.
- يلزم اختبار قبول حي بحسابين مختلفين وعلى هاتف Android بعد نشر النسخة الجديدة، للتحقق من الدعوات والصلاحيات وتبديل التحديات.
