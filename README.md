# تحدّي | CHALLENGE

منصة عربية RTL لمتابعة العادات اليومية والقراءة والمنافسة بين المشاركين. المشروع مبني على Next.js 16 وTypeScript وTailwind CSS 4 وSupabase وRecharts.

## الحالة

هذا المستودع يحتوي على التطبيق وملفات ترحيل قاعدة البيانات اللازمة لتشغيل نسخة أولى مرتبطة بقاعدة بيانات حقيقية. لا توجد بيانات تجريبية أو حسابات جاهزة. يلزم ربط مشروع Supabase وتشغيل ملفات migration قبل تسجيل الحسابات. لم يتم ربط المشروع أو نشره على Vercel بعد.

## التشغيل

1. أنشئ مشروعاً في Supabase.
2. افتح SQL Editor وشغّل ملفات `supabase/migrations` بالترتيب التصاعدي حسب اسم الملف:
   - `202611270001_challenge_schema.sql`
   - `202611270002_hardening_and_scoring.sql`
   - `202611270003_advisor_hardening.sql`
   إذا كانت الملفات السابقة مطبّقة بالفعل، شغّل فقط الملفات التي لم تُطبّق بعد، بالترتيب.
3. في Supabase Authentication → URL Configuration، اضبط Site URL وأضف عنوان الموقع المحلي وعنوان Vercel إلى Redirect URLs، مع المسار `/auth/callback`.
4. انسخ `.env.example` إلى `.env.local`، وأدخل Project URL وPublishable Key من إعدادات مشروع Supabase.
5. نفّذ `npm install` ثم `npm run dev`.
6. افتح `http://localhost:3000`، وأنشئ حساب المنظّم ثم اختر إنشاء تحدّي ديسمبر 2026.
7. من الإعدادات أنشئ رابط دعوة وأرسله للمشارك الثاني. ينشئ المشارك حسابه أولاً ثم يفتح رابط الدعوة.
8. للنشر: اربط المستودع بمشروع Vercel، وأضف متغيرَي Supabase نفسيهما في Production وPreview، ثم انشر الفرع الرئيسي.

## أوامر التحقق

- `npm run test:rules` لاختبار قواعد النقاط والتقويم وفحوصات انحدار مخطط قاعدة البيانات.
- `npm run typecheck` لفحص TypeScript بعد تثبيت الحزم.
- `npm run build` لبناء نسخة الإنتاج بعد ضبط متغيرات البيئة.

## قواعد النقاط

- كل عادة أساسية مكتملة = نقطة واحدة.
- الصيام نقطة إضافية اختيارية ويظهر فقط الاثنين والخميس.
- الحد الأقصى لتحدّي ديسمبر 2026 هو 164 نقطة.
- لا توجد خانة نقاط قابلة للكتابة من المتصفح. النقاط في لوحة المنافسة محسوبة من سجلات الإنجاز.
- قراءة الصفحات محفوظة في `reading_logs` ومستقلة عن عادة القراءة.
- إكمال العادات الأساسية الخمس يكفي لاحتساب اليوم كاملاً ولسلسلة الاستمرارية؛ الصيام يبقى نقطة إضافية.
- `daily_logs.reviewed_at` يميّز اليوم الذي راجعه المستخدم عن اليوم الذي لم يسجل فيه أي شيء.

## الخصوصية والأمان

- RLS مفعّل لكل الجداول، مع سحب صلاحيات الجداول من الدور غير المسجّل.
- سجلات العادات واليوم والقراءة مرئية لصاحبها فقط.
- لا يستطيع المشارك قراءة معرفات عضوية المشاركين الآخرين مباشرة؛ لوحة المنافسة تعرض إحصاءات مجمّعة عبر RPC محمي بعضوية التحدّي.
- وظائف `security definer` تثبّت `search_path` فارغاً وتستخدم أسماء المخططات صراحةً.
- لا يحتاج التطبيق إلى Service Role Key.
- الصيام والتاريخ داخل فترة التحدّي ومنع الأيام المستقبلية يتحقق منها PostgreSQL triggers بتوقيت `Africa/Algiers`.

## حدود النسخة الحالية

- الـPWA قابل للتثبيت على الأجهزة المتوافقة. Service worker يخزّن الأيقونة وملف manifest فقط؛ التطبيق لا يعلن دعماً كاملاً للعمل دون إنترنت أو مزامنة محلية.
- الإشعارات في هذه النسخة تذكيرات متصفح اختيارية أثناء تشغيل التطبيق فقط. Push عند إغلاق التطبيق يحتاج إعداد VAPID/Push service وعملاً خادمياً إضافياً.
- تغيير كلمة المرور متاح من الإعدادات. رفع الصور الشخصية واختيار/إدارة عدة تحديات من واجهة واحدة غير مدعومين في هذه الدفعة.
- الاختبار الفعلي على حسابين وبيئة Supabase حية وAndroid يتطلب تشغيل ملفات migration وإعداد مفاتيح المشروع؛ لم يُثبت بعد نجاح هذه الخطوات في بيئة المستخدم.
