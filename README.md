# تحدّي | CHALLENGE

منصة عربية RTL لمتابعة العادات اليومية والقراءة والمنافسة بين المشاركين. المشروع مبني على Next.js 16 وTypeScript وTailwind CSS 4 وSupabase وRecharts.

## الحالة

هذا المستودع يحتوي على التطبيق وملف SQL المطلوبين لتشغيل نسخة أولى مرتبطة بقاعدة بيانات حقيقية. لا توجد بيانات تجريبية أو حسابات جاهزة. يلزم ربط مشروع Supabase وتشغيل migration قبل تسجيل الحسابات. لم يتم ربط المستودع أو النشر على Vercel بعد؛ يلزم منح اتصال GitHub صلاحية الكتابة أو رفع ملفات الحزمة إلى المستودع.

## التشغيل

1. أنشئ مشروعاً في Supabase.
2. افتح SQL Editor وشغّل `supabase/migrations/202611270001_challenge_schema.sql` كاملاً.
3. في Supabase Authentication → URL Configuration، اضبط Site URL وأضف عنوان الموقع المحلي وعنوان Vercel إلى Redirect URLs، مع المسار `/auth/callback`.
4. انسخ `.env.example` إلى `.env.local`، وأدخل Project URL وPublishable Key من إعدادات مشروع Supabase.
5. نفّذ `npm install` ثم `npm run dev`.
5. افتح `http://localhost:3000`، وأنشئ حساب المنظّم ثم اختر إنشاء تحدّي ديسمبر 2026.
6. من الإعدادات أنشئ رابط دعوة وأرسله للمشارك الثاني. ينشئ المشارك حسابه أولاً ثم يفتح رابط الدعوة.
7. للنشر: اربط المستودع بمشروع Vercel، وأضف متغيرَي Supabase نفسيهما في Production وPreview، ثم انشر الفرع الرئيسي.

## أوامر التحقق

- `npm run test:rules` لاختبار قواعد النقاط والتقويم محلياً.
- `npm run typecheck` لفحص TypeScript بعد تثبيت الحزم.
- `npm run build` لبناء نسخة الإنتاج بعد ضبط متغيرات البيئة.

## قواعد النقاط

- كل عادة أساسية مكتملة = نقطة واحدة.
- الصيام نقطة إضافية ويظهر فقط الاثنين والخميس.
- لا توجد خانة نقاط قابلة للكتابة من المتصفح. النقاط في لوحة المنافسة محسوبة من عدد سجلات الإنجاز.
- قراءة الصفحات محفوظة في `reading_logs` ومستقلة عن عادة القراءة.
- `daily_logs.reviewed_at` يميّز اليوم الذي راجعه المستخدم عن اليوم الذي لم يسجل فيه أي شيء.

## الخصوصية والأمان

- RLS مفعّل لكل الجداول.
- سجلات العادات واليوم والقراءة مرئية لصاحبها فقط.
- لوحة المنافسة تسحب الإحصاءات المجمّعة تلقائياً كل 15 ثانية؛ لا تفتح سجلات العادات الخاصة بالمشارك الآخر.
- لوحة المنافسة تعرض إحصاءات مجمّعة عبر RPC محمي بعضوية التحدّي، ولا تكشف تفاصيل العادات اليومية للمشارك الآخر.
- لا يحتاج التطبيق إلى Service Role Key.
- الصيام والتاريخ داخل فترة التحدّي ومنع الأيام المستقبلية يتحقق منها PostgreSQL triggers بتوقيت `Africa/Algiers`.

## حدود النسخة الحالية

- الـPWA قابل للتثبيت على الأجهزة المتوافقة. Service worker يخزّن الأيقونة وملف manifest فقط؛ التطبيق لا يعلن دعماً كاملاً للعمل دون إنترنت أو مزامنة محلية.
- الإشعارات في هذه النسخة تذكيرات متصفح اختيارية، مع تنبيه اختياري عند تغيّر ترتيب المستخدم، أثناء تشغيل التطبيق فقط. Push عند إغلاق التطبيق يحتاج إعداد VAPID/Push service وعملاً خادمياً إضافياً.
- تغيير كلمة المرور متاح من الإعدادات. رفع الصور الشخصية واختيار/إدارة عدة تحديات من واجهة واحدة غير مدعومين في هذه الدفعة.
- الاختبار الفعلي على حسابين وبيئة Supabase حية وAndroid يتطلب مفاتيح مشروع Supabase وبيانات حسابين؛ لا توجد مفاتيح في المستودع.
